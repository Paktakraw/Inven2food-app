# Inven2Food — Design

วันที่: 2026-11-27 · สถานะ: ผู้ใช้อนุมัติแล้ว (แก้ขอบเขตครั้งใหญ่เมื่อผู้ใช้ตัดเรื่องรายการสั่ง/การขายออก)

> ข้อความที่มีป้ายว่า **[การตัดสินใจของผู้ออกแบบ]** คือสิ่งที่ผู้ออกแบบเลือกเอง ไม่ใช่สิ่งที่เจ้าของโปรเจกต์พูดไว้ ให้ตรวจเป็นพิเศษ

## 1. เจตนาและเหตุผล

เจ้าของร้านอาหารกำลังจะเปิดร้าน ต้องการระบบ **จัดการวัตถุดิบภายในร้าน** ใช้คนเดียว **ไม่เกี่ยวกับการรับหรือจัดการรายการสั่งจากลูกค้า** ไม่มีเรื่องการขาย ระบบต้องตอบคำถามเหล่านี้ได้:

- ซื้ออะไรมา วันไหน กี่บาท ปริมาณเท่าไร
- ทำอาหารไปเท่าไร ใช้วัตถุดิบเท่าไร เหลือเท่าไร
- รายการอาหารไหนใช้วัตถุดิบอะไรบ้าง เท่าไร (และทำได้กี่จานจากของที่มี)
- ยังมีของอยู่หรือไม่ จะได้ไม่ซื้อซ้ำ ของไหนใกล้หมดอายุ ของไหนใกล้หมด

การ "ทำอาหาร" ใช้ได้ทุกกรณีเหมือนกัน ทั้งทำกินเอง ชิม และทดลองทำก่อนขายจริง ระบบไม่แยกประเภท ทุกครั้งที่บันทึกการทำ ระบบตัดวัตถุดิบตามสูตรคูณจำนวนจาน

ผู้ใช้คือเจ้าของร้านคนเดียว ใช้มือถือตอนจ่ายตลาด และใช้คอมพิวเตอร์ตอนอยู่ที่ร้าน

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ถือว่าล้มเหลว

**เป้าหมาย**
- วงจรครบ 4 ส่วน: รายการซื้อของ → คลังวัตถุดิบ → รายการอาหารและการทำอาหาร → การแจ้งเตือน
- ตัวเลขของคงเหลือตรงกับของจริง และตรวจย้อนหลังได้ว่าตัวเลขมาจากไหน
- ใช้งานบนมือถือได้สะดวก (โดยเฉพาะส่วนจ่ายตลาด)

**ไม่ใช่เป้าหมาย (เวอร์ชันแรก)**
- **ไม่มีการจัดการรายการสั่งจากลูกค้า** ไม่มีลูกค้า ช่องทางขาย ยอดขาย ราคาขาย หรือกำไร (ผู้ใช้กำหนด)
- ไม่เชื่อมแพลตฟอร์มภายนอกใด ๆ
- ไม่มีหลายผู้ใช้ หลายสิทธิ์ หรือหลายสาขา
- ไม่ใช่ระบบรับชำระเงิน ไม่ออกใบเสร็จ
- ไม่มีแจ้งเตือนแบบ push ข้อความเตือนแสดงในแอปเท่านั้น **[การตัดสินใจของผู้ออกแบบ]**

**สิ่งที่ถือว่าล้มเหลวแม้ระบบจะทำงานได้**
- ตัวเลขของคงเหลือไม่ตรงกับของจริงจนเจ้าของไม่เชื่อถือ
- การกรอกข้อมูลใช้เวลานานกว่าการทำงานจริง จนเลิกใช้
- ตัดผิดรอบที่ซื้อ ทำให้ของเก่าเน่าทิ้ง

## 3. ข้อกำหนดและข้อจำกัด

- ฐานข้อมูลและระบบล็อกอิน: **Supabase** (Postgres + Auth) ผู้ใช้เลือกเอง
- เป็นเว็บแอปที่ใช้ได้ทั้งมือถือและคอมพิวเตอร์ ต้องใช้อินเทอร์เน็ต
- ผู้ใช้คนเดียว ล็อกอินด้วยอีเมล/รหัสผ่าน
- **ทุกอย่างที่ผู้ใช้เห็นต้องเป็นภาษาไทยล้วน ไม่มีภาษาอังกฤษปน** (ผู้ใช้กำหนด): ชื่อหน้า เมนู ปุ่ม เครื่องมือ ชื่อฟังก์ชันการทำงาน ป้ายกำกับ สถานะ ข้อความแจ้งเตือนและข้อผิดพลาด ชื่อแท็บเบราว์เซอร์ ใช้คำศัพท์ตามภาคผนวก ก. ท้ายเอกสาร ชื่อภาษาอังกฤษในเอกสารนี้ (เช่น Pantry, FEFO, Check-in) ใช้อธิบายแนวคิดให้ผู้สร้างเท่านั้น ห้ามปรากฏบนหน้าจอ ข้อยกเว้นมีเพียง 3 คำ: ชื่อแอป Inven2Food, Email และ Password
- โฟลเดอร์โปรเจกต์ยังไม่ใช่ git repository

## 5. แนวคิดของระบบ 4 ส่วน

### 5.1 รายการซื้อของ (ประตูรับเข้า)
- **วางแผนซื้อ:** รายการมาจาก (ก) วัตถุดิบที่ต่ำกว่าจุดสั่งซื้อซ้ำ จากการแจ้งเตือน (ข) ปุ่ม "เพิ่มของที่ขาดเข้ารายการซื้อของ" ที่หน้ารายการอาหารและสูตร เมื่อผู้ใช้ระบุว่าอยากทำรายการอาหารนั้นกี่จานแล้วของไม่พอ **[ข้อเสนอของผู้ออกแบบ แทนข้อ "ขาดสำหรับรายการสั่ง" เดิม]** และ (ค) เพิ่มรายการเอง
- **เตือนซื้อซ้ำ:** ถ้าวัตถุดิบในรายการยังมีในคลัง ให้แสดง "ยังมีอยู่ X (หมดอายุ วันที่ Y)"
- **จ่ายตลาด:** ผู้ใช้ติ๊กของที่ซื้อ แล้วกรอกราคาจริง ปริมาณจริง หน่วยที่ซื้อ และวันหมดอายุ จากนั้นกด **นำเข้าคลัง** เพื่อสร้างรอบที่ซื้อในคลัง โดยไม่ต้องพิมพ์ซ้ำ
- **การแปลงหน่วย:** ซื้อเป็นหน่วยหนึ่ง (กก., ลัง, แพ็ค) ระบบแปลงเป็นหน่วยฐานของวัตถุดิบ (กรัม, มิลลิลิตร, ชิ้น) ตามค่าที่ตั้งไว้ต่อวัตถุดิบ

### 5.2 คลังวัตถุดิบ (แหล่งข้อมูลจริง)
- วัตถุดิบหนึ่งชนิดมีได้หลาย **รอบที่ซื้อ** (Lot) แต่ละรอบเก็บ: ปริมาณคงเหลือ ราคาทุนต่อหน่วยฐาน วันหมดอายุ วันที่ซื้อ และช่องเก็บ
- **ช่องเก็บ:** ช่องแช่แข็ง, ตู้เย็น, ตู้แห้ง
- ปริมาณคงเหลือของวัตถุดิบ = ผลรวมคงเหลือของทุกรอบที่ซื้อ
- **ทุกการเปลี่ยนแปลงยอดบันทึกเป็นรายการเคลื่อนไหว** พร้อมเหตุผล: ซื้อเข้า, ยอดคงเหลือเริ่มต้น, ใช้ทำอาหาร, คืนยอดจากการยกเลิก, ปรับยอดตามการนับ, ตัดทิ้ง **[การตัดสินใจของผู้ออกแบบ]** เพื่อให้ตรวจย้อนหลังได้ ทั้งซื้อวันไหน กี่บาท ปริมาณเท่าไร และใช้ไปกับรายการอาหารไหน
- ผู้ใช้ปรับยอดจากการนับจริงได้ และตัดของหมดอายุทิ้งได้

### 5.3 รายการอาหารและการทำอาหาร (ตัวตัดของ)
- **สูตรต่อ 1 จาน:** รายการอาหารหนึ่งมีรายการวัตถุดิบและปริมาณต่อ 1 จาน (เช่น ไข่เจียว 1 จาน = ไข่ 2 ชิ้น + น้ำมัน 15 มิลลิลิตร) ทำ n จานคูณ n
- **ฟอร์มสร้างรายการอาหาร (ผู้ใช้เห็นด้วยแล้ว):** หน้าเดียวขั้นเดียว มีช่องชื่อและส่วนเลือกวัตถุดิบจากคลังพร้อมปริมาณต่อ 1 จาน กดบันทึกครั้งเดียวได้ทั้งชื่อและสูตร **ต้องมีวัตถุดิบอย่างน้อย 1 อย่างจึงจะบันทึกได้** **[ข้อเสนอของผู้ออกแบบ ผู้ใช้เห็นด้วยแล้ว]**
- **อัตราที่ใช้ได้จริง (yield):** ตั้งค่า % ที่ใช้ได้จริงต่อวัตถุดิบในสูตรได้ เช่น หมู 1 กก. ใช้ได้ 85% ระบบนำไปคิดปริมาณที่ต้องตัดและต้นทุน ค่าเริ่มต้น 100% **[การตัดสินใจของผู้ออกแบบ]**
- **ตรวจความพร้อม:** บอกว่ารายการอาหารทำได้กี่จานจากของคงเหลือ และถ้าอยากทำ n จาน ขาดอะไรเท่าไร
- **บันทึกการทำ:** ปุ่ม "บันทึกการทำ" ใช้ได้ทั้งทำกินเอง ชิม และทดลองสูตร โดยเลือกรายการอาหาร ใส่จำนวนจาน และหมายเหตุ (ข้อความอิสระ ไม่บังคับ) กดบันทึกแล้วระบบตัดของทันทีในขั้นเดียว **ไม่มีสถานะรอทำ** **[ข้อเสนอของผู้ออกแบบ ตามที่ผู้ใช้ให้ยุบเหลือแนวคิดเดียวคือ "จำนวนที่ทำ"]**
- **ตัดตามหลักใช้ของที่หมดอายุก่อน (FEFO):** ใช้รอบที่ซื้อที่หมดอายุใกล้ที่สุดก่อน ถ้ารอบเดียวไม่พอให้ตัดต่อจากรอบถัดไป บันทึกต้นทุนจริงของการทำนั้นจากราคาทุนของรอบที่ใช้
- **ถ้าของไม่พอ:** ระบบไม่ตัดเลย แสดงสิ่งที่ขาด และให้ผู้ใช้ปรับยอดหรือเปลี่ยนจำนวน **[การตัดสินใจของผู้ออกแบบ]**
- **ยกเลิกการทำ:** ใช้เมื่อบันทึกผิด คืนยอดเข้ารอบที่ซื้อเดิมตามรายการเคลื่อนไหวที่บันทึกไว้ ไม่มีการแก้ไขบันทึกที่ทำแล้ว ถ้าผิดให้ยกเลิกแล้วบันทึกใหม่ **[การตัดสินใจของผู้ออกแบบ]**
- **ประวัติ:** หน้าประวัติทำอาหารแสดงว่าทำอะไร กี่จาน เมื่อไร ต้นทุนเท่าไร

### 5.4 การแจ้งเตือน (เฝ้าระวังเชิงรุก)
แสดงในแอป (หน้าหลัก) **[การตัดสินใจของผู้ออกแบบ ทั้งหมวดนี้ ผู้ใช้ให้เฉพาะแนวคิดว่าเป็นผู้ช่วยเฝ้าระวังเพื่อกันของเน่าและของหมด]**
- **ใกล้หมดอายุ:** รอบที่ซื้อที่หมดอายุภายใน N วัน (ค่าเริ่มต้น 3 วัน ตั้งต่อวัตถุดิบได้) เรียงตามวันหมดอายุ
- **ของใกล้หมด:** วัตถุดิบที่คงเหลือต่ำกว่าจุดสั่งซื้อซ้ำที่ตั้งไว้ต่อวัตถุดิบ
- **ซื้อซ้ำ:** แสดงในรายการซื้อของตามข้อ 5.1
- รายการของใกล้หมดส่งต่อเข้ารายการซื้อของ (วางแผนซื้อ) ได้

## 6. ต้นทุน
- ต้นทุนของการทำแต่ละครั้ง = ผลรวม (ปริมาณที่ตัดจากแต่ละรอบที่ซื้อ × ราคาทุนของรอบนั้น)
- ต้นทุนโดยประมาณต่อจานของรายการอาหาร (ก่อนทำ) คิดจากราคาทุนเฉลี่ยถ่วงน้ำหนักของรอบที่คงเหลือ

## 6.1 กติกาเพิ่มเติม — ทั้งหมดเป็น **[การตัดสินใจของผู้ออกแบบ]**

**หน่วย**
- วัตถุดิบหนึ่งชนิดมี **หน่วยฐานเดียว** (กรัม, มิลลิลิตร, ชิ้น) และ **สูตรเขียนเป็นหน่วยฐานนี้เสมอ**
- หน่วยที่ซื้อ (กก., ถาด, ขวด, ลัง) กำหนดเป็นตัวคูณเข้าหน่วยฐานต่อวัตถุดิบ เช่น ไข่ 1 ถาด = 30 ชิ้น, น้ำมัน 1 ขวด = 1000 มิลลิลิตร ไม่ต้องมีการแปลงข้ามชนิดหน่วย (เช่น กรัม↔ชิ้น) ถ้าสูตรต้องการ ให้เลือกหน่วยฐานของวัตถุดิบให้ตรงกับที่ใช้ในสูตร

**ยอดคงเหลือเริ่มต้นและการปรับยอด**
- เพิ่มรอบที่ซื้อเองได้นอกรายการซื้อของ เหตุผลการเคลื่อนไหวเพิ่ม "ยอดคงเหลือเริ่มต้น" สำหรับของที่มีอยู่ก่อนเปิดร้าน
- การปรับยอด **เพิ่ม** จากการนับ สร้างรอบที่ซื้อใหม่ ราคาทุนเริ่มต้นเท่าราคาทุนเฉลี่ยของวัตถุดิบนั้น (แก้ได้) วันหมดอายุไม่บังคับ
- การปรับยอด **ลด** ตัดตามหลักใช้ของที่หมดอายุก่อน

**อัตราที่ใช้ได้จริง**
- ปริมาณในสูตรคือปริมาณที่ใช้จริงต่อ 1 จาน ปริมาณที่ตัดจากคลัง = ปริมาณในสูตร ÷ อัตราที่ใช้ได้จริง (85% → ตัด 1/0.85 เท่า) ต้นทุนของการทำรวมส่วนที่เสียด้วย

**หลักใช้ของที่หมดอายุก่อนและของหมดอายุ**
- รอบที่ซื้อที่เลยวันหมดอายุ **ไม่นับ** ในจำนวนที่ทำได้ ไม่นับในยอดเทียบจุดสั่งซื้อซ้ำ และการตัดจะข้ามรอบนั้น แสดงเป็นรายการให้ตัดทิ้ง (บันทึกเป็นของเสีย)
- รอบที่ไม่มีวันหมดอายุ (ของแห้ง) เรียงหลังสุด

**การยกเลิกการทำ**
- ยกเลิกคืนยอดเข้ารอบที่ซื้อเดิม แม้รอบนั้นหมดอายุแล้ว (จะไปอยู่ในรายการของหมดอายุให้ตัดทิ้ง) รอบที่ซื้อที่มีรายการเคลื่อนไหวอ้างถึงห้ามถูกลบ (เก็บเป็นยอด 0 แทน) จึงคืนยอดได้เสมอ
- ตอนบันทึกการทำใช้สูตรฉบับปัจจุบัน ณ เวลานั้น และบันทึกปริมาณที่ตัดจริงไว้ในรายการเคลื่อนไหว (ไม่ต้องทำเวอร์ชันของสูตร)

**รายการซื้อของ โหมดวางแผน**
- ส่วนที่ขาด = ปริมาณที่ผู้ใช้ระบุว่าอยากทำ หักด้วยของที่ใช้ได้ (ไม่หมดอายุ) บวกกับวัตถุดิบที่ต่ำกว่าจุดสั่งซื้อซ้ำ

**นำเข้าคลัง**
- ราคาที่กรอกคือ **ราคารวมของแถวนั้น** ระบบคำนวณต้นทุนต่อหน่วยฐาน เก็บเป็นตัวเลขทศนิยมความละเอียดสูง ไม่ปัดเศษ
- ซื้อหลายหน่วยที่วันหมดอายุต่างกัน ให้แยกเป็นหลายแถว (หลายรอบที่ซื้อ)

**การใช้งานที่ตลาด**
- ไม่ต้องใช้แบบออฟไลน์เต็มรูปแบบ แต่รายการซื้อของเก็บฉบับร่าง (ติ๊กและราคาที่กรอก) ไว้ในเบราว์เซอร์ ไม่หายถ้าสัญญาณหลุดหรือหน้าถูกรีเฟรช ก่อนกดนำเข้าคลัง
- ยังไม่มีโปรเจกต์ Supabase จะต้องสร้างตอนเริ่มลงมือ ที่โฮสต์เว็บให้ผู้สร้างเลือก

**รูปแบบการแสดงผล**
- ภาษาไทย สกุลเงินบาท วันที่แสดงและกรอกเป็น `dd/mm/yy` ปี พ.ศ. สองหลัก เช่น 27/11/69, 01/12/69 (ผู้ใช้กำหนด) แต่เก็บในฐานข้อมูลเป็นรูปแบบสากล (ISO) ช่องกรอกวันที่เป็นช่องข้อความเฉพาะ ไม่ใช้ช่องวันที่ของเบราว์เซอร์ เพราะรูปแบบที่แสดงขึ้นกับภาษาของเครื่อง

## 7. สิ่งที่ปล่อยให้ผู้สร้างตัดสินใจ
- เฟรมเวิร์กหน้าบ้านและโครงสร้างโค้ด ตราบที่ใช้งานบนมือถือได้ดีและเชื่อม Supabase ได้
- ชื่อตาราง โครงสร้างสคีมา และ Row Level Security
- หน้าตา UI รายละเอียดปุ่มและลำดับหน้า
- ลำดับการสร้าง (ข้อเสนอ: วัตถุดิบ+รอบที่ซื้อ → สูตร → บันทึกการทำ+ตัดของ → รายการซื้อของ → การแจ้งเตือน)
- วิธีทดสอบ โดยตรรกะตัดของ การแปลงหน่วย และการคืนยอดเมื่อยกเลิกควรมีการทดสอบอัตโนมัติ
